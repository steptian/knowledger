knowledger · 完整链路图文档进 → 索引卡出 → 人审 → 编译 → AI 只读快照 · 三个入口（CLI / MCP / HTML）· 六道机械关

核心是一条单向数据链：原样文档 → 机器索引卡 → 人审过的实例 → 编译产物。三件事只能往右走，不能跳：没人审的卡不进编译，没人审的边不进快照。所有编辑都发生在 blocks/，raw/ 永远只增不改。

01数据链路

STAGE 1 · 只增不改
raw/
原样文档，零改名零改结构。每个文件一个 sha 指纹。
  • 进什么　.md .txt .html .csv .json 直接读
  • .docx .xlsx → 旁车 .md（待做）· .doc .pdf → 只建卡需 OCR · 飞书 / Notion → 需凭证，插件
→
STAGE 2 · 待审区
staging/
每份文档一张索引卡（type=Doc，status=draft）。owner=待审 → 不进编译。
  • 机器做　推断归属块（路径优先 / 关键词计分）· 切候选条目（API 表行 / 三级标题 / 加粗要点）· 算源 sha
→
STAGE 3 · 唯一编辑面
blocks/
审过的实例，按块分目录。所有 frontmatter 编辑、approve、move 都在这里落盘。
  • 人审　填 owner（关 3 查权限）· 写定义（对照源文）· 审边 ok / wrong（关 6，by 必须是块 owner）
→
STAGE 4 · 可重建产物
build/
ontology.json · SNAPSHOT.md · rewrite.json · graph.json / .html / .mmd。deprecated 和 wrong 边物理排除。
  • 编译　extract（实体 / 边 / 候选 / rewrite 表）· check 三关（格式 / 指纹漂移 / 回溯）· recall（词重叠 + 别名归一 + 一跳邻居）

02人或 Agent 怎么与它交互（三个入口，同一套动词）

CLI
人和 Agent 共用。
从 kb 目录任意子目录运行，向上找 knowledger.yaml。
knowledger scan <目录>→ knowledger cards→ knowledger review cards→ 编辑卡：填 owner / 写定义 / 移进 blocks/→ knowledger review edges→ knowledger approve <card> <rel> <other> ok --by <owner>→ knowledger check→ knowledger build→ knowledger recall "…" · knowledger graph · knowledger review tree · knowledger drift
MCP
任何 MCP 客户端：WorkBuddy / 豆包 / Claude / Cursor。
knowledger serve（stdio），需 knowledger[mcp]。
knowledger_status谁拥有哪个块 → knowledger_review_edges待审边 + 两端定义 + 源文行 → Agent 念给 owner 听，owner 一个字：对 / 错 / 错在哪端→ knowledger_approve(by=owner)非 owner 被拒，error 带 hint → knowledger_check→ knowledger_build→ knowledger_recall · knowledger_get · knowledger_tree · knowledger_drift  | 其他写：knowledger_move · knowledger_set_definition · knowledger_add_card
HTML
人想「一眼看全貌」时。
knowledger open，单文件零依赖。
搜节点 / 按块过滤 / 缩放→ 点节点 → 右侧：定义 · 候选条目 · 所有边（待审标黄）→ 「交给 Agent」块：自动拼好一段指令→ 复制 → 贴给 WorkBuddy / 豆包→ Agent 走 MCP 那条线。图上没有 ✅❌ 按钮——操作全走 CLI / MCP。

03六道机械关：谁在哪一步拦什么

关 1
结构完整
必填齐；sources 必须是 [{doc, version}]；关系名在白名单内
check · build
关 2
术语漂移 + 源漂移
实例名未进 glossary → 待归一队列；raw/ 源 sha 变了 → 待重审（只报不拦）
lint · drift · build[指纹]
关 3
块归属写入
owner 必须在该块 owners 里；owners=null 的块谁都不能写
check · add · move
关 4
时效有效
deprecated 实例物理移出快照（进 _archive/），AI 看不到
snapshot · build
关 5
审批生效
不在包里——由载体承担（git PR / 分支保护）。
外部
关 6
边已人审
active 实例的每条边必须有 review: ok|wrong；approve 的 by 必须是该块 owner（Agent 自编名被拒）；wrong 的边不进产物
check · build · approve

04谁消费 build/

AI 工具（只读）
WorkBuddy / 豆包 / 任意 Agent 挂目录

挂 build/SNAPSHOT.md。按块分、deprecated 已排除、每条带 owner 和源。永远不挂 blocks/ 和 raw/——那是编辑面和原件。

检索层（P5 接入）
query rewrite + 一跳邻居

rewrite.json 做别名→标准术语归一；ontology.json 的 edges 做邻居扩展。召回算法现在是词重叠，可换向量，材料不是规则。

人看全貌
graph.html / Mermaid

graph.html 单文件；graph.mmd 贴飞书画板 / Notion / Obsidian。待审边在两处都标 ⏳。

读 / 导航 写（需权限：块 owner） 校验 / 编译（机械关） 人的判断（不可跳过）
不变量　① raw/ 只增不改；② 没人审 owner 的卡不进编译；③ 没人审的边不进快照（关 6）；④ 审边的 by 必须是块 owner（和关 3 同一张表）；⑤ build/ 全部可重建，别手改。
